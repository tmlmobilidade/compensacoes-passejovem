Procedimento de Repescagem de NIF

Este anexo documenta o procedimento operacional de repescagem de Números de Identificação Fiscal (NIF) para cartões que surgem sem NIF (semNIF) no ficheiro mensal de validações, cruzando-os com a tabela F_AUX_PROFILE_CARDS noutra base de dados e atualizando o ficheiro cumulativo data/auxiliar/nif_repescagem.csv.

AvisoContinua a fazer sentido

Desde dos dados de setembro de 2026, a extração primária de validações já integra diretamente os NIFs atualizados na base de dados de perfis de cartões. No entanto, há NIFs que podem ser adicionados à BD posteriormente ao mês em análise, e este procedimento garante que conseguimos integrar esses NIFs.

Visão Geral e Ficheiros Envolvidos

O ficheiro data/auxiliar/nif_repescagem.csv é uma tabela cumulativa que reúne todos os pares (card_serial_number, fiscal_number) recuperados desde os dados de 2024 até ao mês de referência mais recente, acompanhados pela coluna ano_mes (ex.: 202412 para a base original de 2024 e 202608 para os NIFs recuperados no apuramento de agosto de 2026).

No Passo 01 do pipeline (code/01_preparar_dados.R), esta tabela é filtrada automaticamente por ano_mes <= ano * 100 + mes (filtrar_ate_ano_mes()) e cruzada por card_serial_number para preencher o fiscal_number exclusivamente onde este vem em falta (NA), garantindo que novos NIFs adicionados em meses seguintes nunca alteram retroativamente os resultados de meses já encerrados. Adicionalmente, no fecho de cada mês, a função bloquear_auxiliares_mes(ano, mes) guarda uma cópia congelada das tabelas auxiliares em data/<ano>_<mm>_<mes>/input/auxiliar_lock/.

O fluxo de atualização mensal para recuperar NIFs de novos cartões semNIF recorre a três scripts auxiliares:

Ficheiro Localização Função no Procedimento
repescagem_add.R code/test/ 1) Identifica os novos cartões semNIF face ao mês anterior;
2) Funde os novos NIFs recuperados no ficheiro cumulativo data/auxiliar/nif_repescagem.csv e verifica a sobreposição com comNIF.
repescagem_nif_otherDB.sql data/auxiliar/ Query SQL à tabela F_AUX_PROFILE_CARDS para verificar se os cartões semNIF já possuem FISCAL_NUMBER preenchido noutra base de dados.
insert_repescagem202610.sql data/auxiliar/ Script SQL de atualização da tabela public.nif_repescagem2024 na base de dados PostgreSQL (dep > public).

Passo a Passo Operacional

Passo 1 — Identificar novos cartões semNIF no mês de referência

Após uma primeira execução dos Passos 01 e 02 do pipeline para o novo mês (ex.: agosto de 2026), comparam-se os registos semNIF do mês em análise com os do mês anterior (ex.: julho de 2026) usando a segunda metade do script code/test/repescagem_add.R:

# Casos sem NIF que surgiram em Agosto e não estavam em Julho
agosto_semNIF <- read_delim("data/2026_08_agosto/output/2026_08_semNIF.csv", 
                            delim = ";", escape_double = FALSE, trim_ws = TRUE)
julho_semNIF  <- read_delim("data/2026_07_julho/output/2026_07_semNIF.csv", 
                            delim = ";", escape_double = FALSE, trim_ws = TRUE) 

semNIF_compare0807 <- agosto_semNIF |>
  select(card_serial_number, doc_type, doc_number, age_new) |> 
  anti_join(julho_semNIF |>
    select(card_serial_number, doc_type, doc_number, age_new)) |> 
  arrange(doc_type, age_new)

# Extrair o vetor de números de série de cartão sem NIF
semNIF_compare0807$card_serial_number

Formatação da lista de cartões para SQL (via Notepad++):

  1. Copiar o output de semNIF_compare0807$card_serial_number da consola do R para o Notepad++;
  2. Substituir espaços por vírgulas e garantir vírgula no final de cada linha;
  3. Unir todas as linhas numa única linha através do menu Edit \(\to\) Line Operations \(\to\) Join Lines.

Passo 2 — Consultar a tabela F_AUX_PROFILE_CARDS noutra Base de Dados

Colar a lista de números de série de cartão na cláusula IN (...) do script data/auxiliar/repescagem_nif_otherDB.sql e executar a consulta na base de dados onde reside F_AUX_PROFILE_CARDS:

-- Check if the semNIF already have a NIF nowadays, in a different DB...
SELECT DISTINCT
    FISCAL_NUMBER,
    SERIAL_NUMBER AS card_serial_number,
    TO_CHAR(BIRTH_DATE, 'YYYY-MM-DD') AS birth_date
    -- CARD_NUMBER,
    -- TO_CHAR(CARD_DATE, 'YYYY-MM-DD') AS card_date,
    -- TO_CHAR(PROFILE_DATE, 'YYYY-MM-DD') AS profile_expiration_date
FROM F_AUX_PROFILE_CARDS
WHERE FISCAL_NUMBER IS NOT NULL
  AND SERIAL_NUMBER IN (
      3310902343, 3310956239, 3310778159, 3277465349, 3310788194 -- substituir aqui
  );

Exportar o resultado da query para um ficheiro CSV (separado por ;, com as colunas card_serial_number e fiscal_number) na pasta data/auxiliar/ — por exemplo, data/auxiliar/nif_repescagem202610.csv.

Passo 3 — Atualizar o ficheiro cumulativo nif_repescagem.csv e voltar a correr a Fase 1

Com o novo ficheiro exportado (ex.: nif_repescagem202610.csv), executar o bloco inicial de code/test/repescagem_add.R para incorporar os novos registos sem duplicados no ficheiro cumulativo data/auxiliar/nif_repescagem.csv:

library(readr)
library(tidyverse)
library(dplyr)

nif_repescagem <- read_csv(
  "data/auxiliar/nif_repescagem.csv", 
  col_types = cols(fiscal_number = col_character())
)

nif_repescagem202610 <- read_delim(
  "data/auxiliar/nif_repescagem202610.csv", 
  delim = ";", escape_double = FALSE,
  col_types = cols(fiscal_number = col_character()), 
  trim_ws = TRUE
) |>
  mutate(ano_mes = 202608L) # identificar o mês de apuramento (AAAAMM)

nif_repescagem_update <- nif_repescagem |> 
  bind_rows(nif_repescagem202610) |> 
  distinct(card_serial_number, fiscal_number, .keep_all = TRUE)

write.csv(nif_repescagem_update, "data/auxiliar/nif_repescagem.csv", row.names = FALSE)
DicaVerificação de Sobreposição e Reexecução do Pipeline

O script code/test/repescagem_add.R inclui também um bloco intermédio (semi_join e anti_join com <ano>_<mm>_comNIF.csv) que permite verificar quantos dos cartões/NIFs recuperados já constavam em comNIF (por terem outro cartão com NIF) e quantos são efetivamente novos.

Após gravar data/auxiliar/nif_repescagem.csv, deve voltar-se a correr a Fase 1 do pipeline (01_preparar_dados.R, 02_calcular_compensacoes.R e 03_exportar_reporte.R) para que os cartões recuperados passem de semNIF para comNIF. Quando o mês estiver validado e fechado, executar bloquear_auxiliares_mes(ano, mes) para congelar uma cópia exata em data/<ano>_<mm>_<mes>/input/auxiliar_lock/.

Passo 4 — Sincronizar a tabela na base de dados PostgreSQL (dep)

Para manter a tabela public.nif_repescagem2024 da base de dados PostgreSQL (dep > public) sincronizada com o ficheiro cumulativo, pode seguir-se uma das duas opções documentadas em data/auxiliar/insert_repescagem202610.sql:

Opção A: Substituição integral por upload do CSV cumulativo

  1. Eliminar a tabela existente (DROP TABLE public.nif_repescagem2024;);
  2. Importar uma nova tabela a partir do ficheiro atualizado data/auxiliar/nif_repescagem.csv, definindo os tipos de dados:
    • card_serial_number como varchar;
    • fiscal_number como int4.

Opção B: Inserção incremental

INSERT INTO public.nif_repescagem2024 (card_serial_number, fiscal_number)
VALUES
  ('2021143730', '322555668'),
  ('2021440603', '278899001')
ON CONFLICT (card_serial_number) DO UPDATE
SET fiscal_number = EXCLUDED.fiscal_number;
